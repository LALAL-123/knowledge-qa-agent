# 05 复盘

> 初稿，按本人实际体会修改。

## 最难的问题

**冲突该由谁判断。** 最省事的做法是在系统里预置“D01 与 D02 冲突”，但那样 Agent 只是在执行查表，替换文档后就失效。最后的划分是：冲突识别和是否追问交给模型；护栏只做能机械判定的事——引用必须逐字来自读过的原文，答案里的数字必须在引用中出现。这样“擅自回答 15 天却只引用 D01”会被护栏拦下，而“漏读 D02”会在验收用例中暴露。

**怎样让“改写后的相似问题”真正考到改写。** 强检索器会把口语问题直接匹配上，模型不需要做任何决策。这里刻意用字符二元组检索，“每年能歇多久”与“年假”无重合必然落空，模型必须看到 `count=0` 后自己改写查询。

**引用的可校验性。** 只要求“给出出处”时，模型常常转述原文。要求 quote 逐字摘录后，可以用子串匹配机械校验，转述的引用直接删除。

## 学习收获

- 知识问答的关键缺陷大多出在“答案与证据不一致”，所以护栏应围绕证据设计，而不是围绕答案文本。
- 替换资料是最直接的效果验证：同一问题，删掉一份文档（c03）或改一句原文（c11），答案和动作都应随之变化。
- 追问要区分“有上下文能补全”和“没有上下文只能澄清”，两种情况都应成为用例。
- 护栏和检查必须同一口径：引用比对在护栏里忽略了空白，检查里没有，第 2 轮 c11 因此误判。两处逻辑应共用一个函数。

## 下一步

1. GLM-4-Flash 两轮 c02 都只读第一条结果。下一步把“多来源”做成工具事实（search_docs 按事项分组返回来源数），并让护栏在只读了其中一个来源时退回模型；再换 1–2 个更强的模型对比冲突识别率。
2. 给文档加优先级与适用范围元数据（如“本说明优先于 D01，仅适用于销售部”），让模型在有依据时裁决冲突、无依据时追问。
3. 增加语义层面的支撑检查（例如用另一个模型判断引用是否回答了问题），弥补数字核对的盲区。
4. 换成向量 + 关键词混合检索后，比较改写查询的收益是否下降。
